# 0.1.0 — Initial CLI

[中文](0.1.0.zh-CN.md)

## Problem and logical changes

The author had a published skill but no installable command for managing its released versions and invoking a local host. This release adds five commands, the reviewed-source catalog, stable tag/commit and exact payload verification, safe sidecar ownership/transactions, known local conflict checks, and local host launch without stored model keys or permission bypasses. It includes the matching English/Chinese usage, maintenance and recovery documents.

The initial catalog contains aesthetic-design only. Its public nine-image distribution is fetched on demand; the private complete image archive is excluded. New author skills and new package formats require reviewed catalog/CLI releases, not arbitrary runtime URLs.

## Actual test-first evidence

On 2026-11-06 at 08:49:56 UTC, the first installation acceptance ran under Node 24.22.2 against the minimal no-op manager: the command returned, but the requested project's SKILL.md did not exist. Expected exit 0, actual test exit 1, `false !== true`. This was a real installation assertion, not a missing import. Implementation then made that same acceptance pass.

During implementation, boundary tests covered real temporary Git tags, payloads and filesystem transitions. Review also exposed two observable compatibility defects; each received a regression before its correction:

- A valid unrelated Claude skill with omitted name blocked use. The actual test failed because the parser required explicit name, then passed after conflict inspection used Claude's folder default. Registered source packages still require an explicit matching name.
- A real isolated process-group SIGINT left the manager lock after its wrapper exited. The actual test failed on `lock remains = true`; after signal handling, group SIGINT and parent-only SIGTERM both completed without duplicate Ctrl-C forwarding and released the lock. Forced process exit remains a separate recovery case.

Fixture import/configuration failures were not counted as business Red evidence. Raw commands, timestamps, output and exits are retained outside the public package; the shared JSON records truthful sanitized summaries. Tests never replace HOME/CODEX_HOME or call paid model sessions.

## Verification

The final `npm test` ran 28 business tests and passed all 28 under Node 24.22.2 on macOS arm64. The JSON companion records the actual result and a real public-source temporary-project install, independent offline validation, update/list and uninstall of all 190 files. Real fixture tests cover both hosts/scopes, actual later-tag upgrade, annotated tags, numeric sorting, no downgrade/retag, unsafe links/paths/state, network/hash failures, transaction fault injection, a real child exiting after state replacement, cooperative locks, literal hostile-looking prompts and child status/signals.

## Limits and rollback

macOS arm64 and Node 24 were used. Linux/native Windows, live model activation/classification accuracy, all host-managed skill sources, hostile same-user filesystem races and real hardware/power-failure durability were not established. Ordinary exceptions restore the old pair; interrupted transactions require the documented manual recovery. After journal removal the new installation is committed, so cleanup failure preserves it rather than rolling back a possibly partial backup.

The package uses no runtime npm dependencies or install lifecycle hooks. Original CLI code/docs use MIT; installed skill and third-party content retain their own terms. To roll back a later CLI release, reinstall a prior verified tag and retain logs. Do not mutate published tags or use a CLI downgrade to force a skill downgrade. No repository or external state was published by implementation.
